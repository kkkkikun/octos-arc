# 01 · 参赛路线与提交流程

2026-09-20 ｜ 本 fork（kkkkikun/octos-arc）= GOSIM Factory26 黑客松（初赛 9/21）参赛主战场。

## 为什么是它（决策史，一句话版）

- 原路线 claude-code 内核被比赛网关阻塞：网关只说 OpenAI 协议，`/v1/messages` 400，
  官方 claude-code 模版把模型错误吞成"假成功"→ 0/30（证据链见 Aurora-X
  `docs/thinks/claude-code-kernel-blockers.md`，shim 已建成并验证但维护成本高）。
- 自研编排（原子节点 + 契约 prompt + 回归守卫）在 keep REQ-2 上 15/23，但回归守卫
  实验暴露自身 bug（4/23 无效）；ARC 官方模版对照显示其调用密度 ≈ 我方 12 倍、
  瞬态错误零容忍，`p/cost` 无胜算。
- octos-arc 是官方团队的参赛版：骨架轮 → 逐节点「设计→实现→**本地跑该节点验收
  spec**→修复≤5轮→commit」，外加回归检查点（每 4 节点重跑已过用例）——正是我方
  缺的环内验证，且 38 轮平台实战打磨。**9/20 云端首跑效果很好，路线坐实。**

## 提交机制（一条主线）

zip 里**不含二进制**：评测机运行时按 zip 内 `arc/main.py` 顶部的 `OCTOS_RELEASE_URL`
现场下载 Octos 内核，再用 zip 里的 Python 编排器驱动做题。

- 只改 Python（`arc/` 提示词/参数/编排）→ 跳过编译发版，改完 `sh arc/pack.sh` → 上传。
- 改了 Rust 内核（`crates/`）→ 必须：push → Actions 手动跑 **"ARC Linux x86_64
  release"**（自动构建+打包+容器冒烟+`gh release create` 到本 fork）→ 把
  `arc/main.py` 的 `OCTOS_RELEASE_URL` 指向新 Release → `pack.sh` → 上传。
  **提交用二进制一律用 CI 产物（ubuntu-latest/glibc 2.39），不用本机编译。**

## 官网提交流程

1. `sh arc/pack.sh` → `octos-arc-bundle.zip`（main.py 在 zip 根，~156KB；
   public-tests 有意不进包，平台挂载 `/workspace/tests`）
2. arc-bench.com 比赛页 → New Submission → 上传 zip
3. 模型 `deepseek-v4-flash`；Base URL `https://api.arc-bench.com/v1`
4. 选题（bookstack）→ Run；评测 40min~3h

## 本机开发循环（不花评测名额）

```sh
export ARCBENCH_API_KEY=$(grep '^api_key=' ~/tmp/agentic-software-engineering-hackathon/Lab/Lab02/.env | cut -d= -f2)
export OCTOS_BIN=~/.cache/octos-arc/bin/octos
export OCTOS_ARC_PLAYWRIGHT_ROOT=~/.cache/octos-playwright

# 做题（bookstack 全量 34 节点；smoke--counter ~10min/$0.012 验链路）
python3 arc/run-task-local.py arc/tasks/arc-bench-web--bookstack --name <tag>

# 评分（平台同款 Playwright）+ 指标（轮数/Token/费用/节点状态）
python3 arc/grade-local.py arc/arc-output/<tag> arc-bench-web--bookstack
python3 arc/metrics.py arc/arc-output/<tag>
```

改前改后各跑一次比数字；重要改动记 `arc/CHANGELOG.md`（官方惯例）。
bookstack 需求树与本仓库 `arc/tasks/arc-bench-web--bookstack/` 一致（34 ATOMIC）。
