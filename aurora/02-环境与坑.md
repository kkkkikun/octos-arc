## 坑 1：官方二进制要 glibc 2.38+，本机 2.35

Release 的 x86_64 全系列都是高 glibc 构建（无 2.35 版）。解法：Ubuntu 24.04 的
libc6 2.39 deb 解包 + patchelf 改 interpreter/rpath，**不动系统 glibc**：

```sh
# 一次性重建（~/.cache/octos-arc 丢了时）
mkdir -p ~/.cache/octos-arc/{bin,glibc} && cd ~/.cache/octos-arc/glibc
curl -fsSL -o libc6.deb "http://mirrors.aliyun.com/ubuntu/pool/main/g/glibc/libc6_2.39-0ubuntu8.9_amd64.deb"
dpkg-deb -x libc6.deb root
cd ../bin
curl -fsSL --http1.1 -C - --connect-timeout 30 --speed-limit 10240 --speed-time 60 --retry 2 \
  -o octos-bundle.tar.gz "https://gh-proxy.com/https://github.com/octos-org/octos-arc/releases/download/v2.0.3-rc.11-arc.13/octos-bundle-x86_64-unknown-linux-gnu.tar.gz"
tar xzf octos-bundle.tar.gz octos octos-sandbox && chmod 755 octos octos-sandbox
GL=~/.cache/octos-arc/glibc/root/usr/lib/x86_64-linux-gnu
patchelf --set-interpreter $GL/ld-linux-x86-64.so.2 --set-rpath $GL octos
octos --version   # 应输出 octos 2.0.3-rc.11 (7f9a5d99 2026-09-15)
```

注意：换目录后必须重新 patchelf（rpath 是绝对路径）。octos-sandbox 无需处理。
**平台端不受此影响**——评测机 glibc 新，且用的是 CI 产物。

## 坑 2：Playwright 官方 CDN 国内超时

编排器验收时私有安装 @playwright/test 会卡死在 chromium 下载（497s 超时），然后
整轮验收降级为「只看终检」——环内验证全废。解法：npmmirror 预装 + 环境变量指路：

```sh
# 一次性重建
mkdir -p ~/.cache/octos-playwright && cd ~/.cache/octos-playwright
PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright/ npm install @playwright/test@1.63.0 --no-fund --no-audit
PLAYWRIGHT_DOWNLOAD_HOST=https://npmmirror.com/mirrors/playwright/ ./node_modules/.bin/playwright install chromium

# 用法
export OCTOS_ARC_PLAYWRIGHT_ROOT=~/.cache/octos-playwright   # 做题时编排器直接用
ln -s ~/.cache/octos-playwright <repo>/arc/local-grader       # 评分时（已建软链）
```

平台端无此问题（评测机网络正常，编排器会自己装）。

## 坑 3：git 通道

- `git push` https 会被网络重置；gh-proxy 不支持 push 认证 → **push 走 SSH**
  （origin 已设 `git@github.com:kkkkikun/octos-arc.git`，密钥已验证）
- 同步上游：`git fetch upstream`（remote 走 gh-proxy 镜像）

## 坑 4：官方脚本首跑 bug（已修）

`arc/grade-local.py` 原版在 `local-grader/` 不存在时用未定义的 `env`（NameError）
——首次运行路径官方没测过。已修（commit f9ebb9a，env 定义提前），已推 fork。

## 坑 5：run-task-local.py 的预算默认值与平台不一致

`run-task-local.py` 写死 `OCTOS_TIME_BUDGET=3600`（1h 上限，不随节点数放大），
而平台默认 = `max(3600, 1500×节点数)`。多节点题不显式设预算会被截断出半成品
（大量节点 time budget exhausted 被跳过），基线数据失真。**本地跑 T1+ 题目必须
`export OCTOS_TIME_BUDGET=$((1500*节点数))`**（keep=48000，bookstack=51000）。
